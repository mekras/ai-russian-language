# DR-0001: Порядок принятия проектных решений

Статус: Принято

Дата: 2026-07-19

Способ принятия: ручное одобрение владельца проекта в диалоге настройки

## Контекст

Проекту нужен единый способ фиксировать значимые долгоживущие решения и
сравнивать варианты. Без общего журнала и порядка факторов решения могут
теряться между задачами, а их обоснования — расходиться.

Для проекта установлены два фактора в порядке важности:

1. Надёжность работы правил.
2. Экономия контекста.

## Рассмотренные варианты

1. Не вести журнал. Это не требует сопровождения, но не сохраняет основания
   долгоживущих решений.
2. Записывать решения без общего порядка. Это сохраняет часть истории, но не
   обеспечивает единообразное сравнение вариантов.
3. Вести единый журнал DR с общей статусной моделью и порядком факторов. Это
   требует сопровождать индекс и записи, но делает решения прослеживаемыми.

## Решение

Все значимые долгоживущие решения проекта записываются в `docs/DR/`. Для
записей используются статусы «Предложено», «Принято», «Отклонено», «Устарело»
и «Заменено».

Варианты сравниваются сначала по надёжности работы правил, затем по экономии
контекста. Если эти факторы не дают явного выбора, решение принимает владелец
проекта. Решение начинает действовать только после его явного принятия
владельцем.

## Последствия

- Основания значимых долгоживущих решений и условия их пересмотра сохраняются
  в репозитории.
- Надёжность правил имеет приоритет над экономией контекста.
- Для каждой новой записи нужно обновлять индекс журнала.
- Обычные локальные решения одной задачи не требуют DR.

## Проверка и пересмотр

Новая значимая запись должна находиться в `docs/DR/`, иметь один из
установленных статусов, сравнивать варианты в принятом порядке и содержать
условие пересмотра.

DR-0001 пересматривается, если владелец меняет порядок факторов, область
журнала, статусную модель или способ принятия решений.
